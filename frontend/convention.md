# React 클린 코드 가이드라인

## 1. 깨끗하고 모듈화된 컴포넌트 설계

### 1.1 컴포넌트의 단일 책임 원칙 (SRP)
- 컴포넌트는 작고 명확하게 하나의 책임만 갖도록 유지함.
- 규모가 커지거나 비즈니스 로직이 복잡해지면 재사용 가능한 작은 단위의 컴포넌트로 분리함.

### 1.2 서술적 명명 규칙 (Naming Conventions)
- 컴포넌트, Props, State, 함수명은 역할을 직관적으로 이해할 수 있도록 명확하고 서술적으로 작성함.
- 자기 설명적(Self-descriptive)인 코드를 지향하여 독해성을 높임.

### 1.3 Props 타입 검증 및 기본값 설정
- **PropTypes:** 전달받는 Props의 타입을 검증하여 개발 단계에서 데이터 타입 관련 버그를 사전에 방지함.
- **DefaultProps:** 선택적(Optional) Props에 대해 기본값을 명시적으로 지정함.

---

## 2. React Hook & Context 활용 규칙

### 2.1 Hook의 최상위 호출 규칙 (Rules of Hooks)
- 모든 Hook (`useState`, `useEffect` 등)은 반드시 함수형 컴포넌트의 **최상위(Top-level)**에서만 호출함.
- 반복문, 조건문, 중첩 함수 내부에서 Hook을 호출하지 않음.
- 매 렌더링마다 동일한 순서로 Hook이 실행되어야 상태 및 동작의 일관성이 보장됨.

### 2.2 Context의 전역 상태 남용 방지
- Context API는 앱 전체에서 접근해야 하는 데이터에 한해 최소한으로 사용함.
- 하위 트리의 일부 또는 단일 컴포넌트에서만 소비되는 데이터는 지역 상태(`useState` 등)로 관리함.

---

## 3. 상태 관리 및 성능 최적화 전략

### 3.1 불필요한 재렌더링 최적화
- **함수형 컴포넌트:** `React.memo`를 활용해 Props 변화가 없을 때의 불필요한 재렌더링을 방지함.
- **클래스형 컴포넌트:** `PureComponent` 또는 `shouldComponentUpdate`를 적용함.

### 3.2 복잡한 상태 로직 처리 (`useReducer`)
- 상태가 다수의 하위 값을 포함하거나 다음 상태가 이전 상태에 의존적인 경우 `useState` 대신 `useReducer` 사용을 권장함.
- 복잡한 상태 전환 및 로직 분리로 코드의 예측 가능성과 유지 보수성을 높임.

### 3.3 코드 분할 및 지연 로딩 (Code Splitting & Lazy Loading)
- `React.lazy`와 `Suspense`를 활용해 필요한 시점에 컴포넌트를 로딩함.
- 초기 JavaScript 번들 크기를 줄여 애플리케이션의 최초 로딩 속도 및 상호작용 성능을 향상시킴.
