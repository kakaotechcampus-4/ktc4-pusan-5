## 0. 한 줄 요약

**관계는 "어디까지 찾아볼지" 를 정하는 데만 쓴다. "실제로 관련 있는지" 는 기사 내용을 보고 다시 판단한다.**

관계 그래프는 근거가 아니라 **후보 생성기(candidate generator)** 다.
관계가 있다는 사실만으로 다른 회사의 기사를 이 회사의 근거로 붙이지 않는다.

## 1. 배경

### 1-1. 팀 질문

> 기업 간 관계(경쟁사, 거래처 등)를 사람이 미리 연결해 두고, 기사에서 추출한 내용을 관련 기업에 전달하는 방식을 생각하고 있다.
> 같은 산업인지, 고객·공급사인지, 지분 관계인지에 따라 연결 범위가 굉장히 넓어질 것 같다.
> 관계가 있어도 기사 내용에 따라 실제 관련성은 달라질 텐데, 미리 정의해서 활용하는 방식이 괜찮은가? 어디까지 연결하고 어떤 기준으로 제한하면 좋은가?

### 1-2. 멘토 피드백 (요지)

- 기업 관계 그래프는 좋은 접근이다. 다만 관계를 **근거**로 쓰기보다, 어떤 기업까지 자료 탐색 범위를 넓힐지 정하는 **후보 생성기**로 쓰는 게 안전하다.
- "A 가 B 의 공급사다" 라는 정보만으로 B 의 모든 뉴스가 A 에게 중요하다고 판단할 수 없다.
- 관계에는 가능하면 **종류(supplier / customer / competitor / ownership 등), 방향, 근거 출처, 유효 기간, 중요도(materiality), 확신도(confidence)** 를 둔다.
- 처음에는 **1-hop** 까지만 확장한다.
- 관계 종류별로 전달 조건을 다르게 본다. 주요 고객의 수요 감소 뉴스는 공급사에 전달할 가능성이 높지만, 같은 산업이라는 이유만으로 모든 기업의 뉴스를 서로 전달하면 노이즈가 크다.
- **관계 그래프는 검색 범위를 좁히는 데 쓰고, 실제 관련성은 기사 내용에서 다시 판단한다.**

## 2. 두 가지 일을 나눈다

| | ① 관계 만들기 | ② 관련성 판정 |
| --- | --- | --- |
| 언제 | 미리. 기사와 무관하게 | 기사가 들어올 때마다 |
| 질문 | "현대모비스와 현대차는 어떤 관계인가?" | "이 현대차 기사가 현대모비스에 영향을 주나?" |
| 누가 | 사람. 자동 추출한 후보를 사람이 확인해도 된다(7절) | 규칙, 필요하면 LLM(6절) |
| 결과 | 관계 그래프(기준 데이터) | 통과 / 탈락 |

- **LLM 이 기사를 읽으면서 관계를 새로 만들지 않는다.** 관계는 미리 정해져 있고, LLM 은 주어진 관계를 통해 이 기사가 영향을 주는지만 판단한다.
  기업–산업 연결의 원칙(INDUSTRY_MAP 0절: "산업–기업 연결을 Jev가 새로 만들지 않는다")과 같다.

## 3. 기업–산업 경로와의 관계 — 대체가 아니라 추가

두 경로는 서로 다른 종류의 사건을 실어 나른다.

| 경로 | 실어 나르는 사건 | 예 (현대모비스 입장) |
| --- | --- | --- |
| 기업–산업 (INDUSTRY_MAP) | 산업 전반 사건 (`scope = industry`) | "자동차 관세 인상" → 자동차부품 산업 → 모비스 |
| 기업–기업 (이 문서) | 특정 회사 사건 (`scope = company`) | "현대차 미국 판매 급감" → 고객 관계 → 모비스 |

- 지금 조립 규칙은 회사 사건을 같은 산업의 다른 회사로 넘기지 않는다(DRAFT 5절). 그래서 두 번째 경우는 지금 잡히지 않는다.
  기업–기업 관계는 이 빈자리를 메우되 판정을 한 번 더 거치게 한다.
- 같은 산업이라는 이유만으로는 여전히 회사 사건을 넘기지 않는다. "같은 산업" 은 관계 종류로 두지 않는다.

## 4. 관계 한 건에 담을 것

한 행 = 사건이 `from` 회사에서 나와 `to` 회사로 전달될 수 있는 **한 방향**. 반대 방향은 전달 조건이 다르므로 따로 적는다.

| 항목 | 뜻 | 예 |
| --- | --- | --- |
| `from` | 사건이 나오는 회사 | 현대차 |
| `to` | 사건을 전달받을 회사 | 현대모비스 |
| `type` | `from` 이 `to` 에게 무엇인가 | `customer` (현대차는 모비스의 고객) |
| `source` | 근거. 공시번호·사업보고서 절·IR 주소 | 사업보고서 "주요 매출처" |
| `valid_from` / `valid_to` | 관계가 유효한 기간. 과거 시점에 지금 관계를 소급하지 않는다 | 2024-01-01 / 비움 |
| `materiality` | 관계가 얼마나 중요한가. 확인 가능한 수치와 기준 기간. 없으면 없다고 적는다 | 매출의 약 40% (2025 사업보고서) |
| `confidence` | 관계 자체를 얼마나 확신하나 | `disclosed`(공시로 확인) / `inferred`(기사·LLM 추정) |
| `status` | 검토 상태. INDUSTRY_MAP 1-1 과 같다 | 미검토 / 확인 / 보류 / 제외 |

`type` 값

| type | 뜻 (`from` → `to`) | 상태 |
| --- | --- | --- |
| `customer` | `from` 은 `to` 의 고객. 고객의 사건이 공급사로 간다 | 쓴다 |
| `supplier` | `from` 은 `to` 의 공급사. 공급사의 사건이 고객으로 간다 | 쓴다 |
| `ownership` | `to` 가 `from` 의 지분을 가졌다. 피투자회사의 사건이 보유 회사로 간다 | 쓴다 |
| `competitor` | 경쟁 관계 | **보류.** 기준이 애매하고 노이즈가 크다(5절) |

- `to` 는 대상 종목(BE `MVP_STOCKS`)이어야 한다. `from` 은 대상 밖 회사(해외 기업 포함)일 수 있다 — 예: LG이노텍의 고객. 대상 밖 회사의 식별자는 아직 정하지 않았다(9절).
- 운영에는 `status = 확인` 인 관계만 쓴다. `confidence = inferred` 는 확인 전 후보로만 둔다.

## 5. 확장 범위

- **1-hop 만.** 현대차 → 현대모비스까지만 보고, 현대모비스의 공급사로는 넘어가지 않는다.
- 관계 종류별 전달 조건. 아래는 판정 단계(6절)의 1차 규칙 초안이다.

| type | 넘길 만한 사건 | 넘기지 않을 사건 |
| --- | --- | --- |
| `customer` (고객 → 공급사) | 수요·판매·발주·생산량·설비투자 변화 | 배당, 인사, 지배구조, 고객의 다른 사업 |
| `supplier` (공급사 → 고객) | 공급 차질, 가격 인상, 생산 중단 | 공급사 자체의 다른 사업 |
| `ownership` (피투자 → 보유) | 실적, 기업가치 변동. 지분이 중요할 때만 | 사소한 운영 뉴스 |
| `competitor` | 처음에는 넘기지 않는다. 점유율 이동이 명시된 기사 정도만 나중에 검토 | 대부분 |

- 판정을 통과해도 **간접 근거**다. 직접 근거로 올리지 않는다(INDUSTRY_MAP 8-2 와 같다).

## 6. 흐름 — 관련성 판정 단계를 둔다

```
종목 A 브리핑
 ① 직접       A 를 대상으로 한 사건
 ② 후보 확장   A 의 산업 사건 (기업–산업)  +  A 와 1-hop 관계인 회사의 사건 (기업–기업)
 ③ 관련성 판정 후보마다 "이 사건이 A 에 어떤 경로로 영향을 주나?" 를 기사 내용으로 확인
              1차: 관계 종류별 전달 조건(5절) — 규칙
              2차: 필요하면 LLM. 관계 종류·방향·사건 문장을 주고 통과/탈락과 이유를 받는다
 ④ 통과한 것만 간접 근거로 브리핑 생성에 넘긴다
```

- 탈락한 후보와 이유도 남긴다. 판정이 맞았는지 나중에 확인하려면 필요하다.
- 2차 LLM 판정은 후보 수만큼 호출이 는다. 실제 기사로 후보가 몇 개나 나오는지 본 뒤 도입을 정한다(9절).

## 7. 관계를 채우는 법

기업을 잘 몰라도 채울 수 있게, 공시로 확인되는 것부터 넣는다.

| type | 출처 | 난이도 |
| --- | --- | --- |
| `ownership` | DART 사업보고서 "타법인 출자 현황" (오픈다트 정기보고서 API 로 구조화된 값을 받을 수 있다) | 쉬움. 자동으로 뽑고 사람은 확인만 |
| `customer` / `supplier` | 사업보고서 "주요 매출처"·"원재료 매입처" | 어려움. "A사" 처럼 이름을 가린 경우가 많다. 이름이 나온 것만 넣는다 |
| `competitor` | 정해진 출처 없음 | 보류 |

- LLM 은 사업보고서를 읽고 관계 **후보**를 뽑는 보조로 쓸 수 있다. 이때 `confidence = inferred`, `status = 미검토` 로 넣고 사람이 확인한다.
- 주가가 같이 움직였다는 사실만으로 관계를 만들지 않는다(INDUSTRY_MAP 1절과 같다).

## 8. 지금 상태와 정리할 것

**코드에는 기업–기업 관계가 없다.** 지금 있는 것은 기업–산업 경로뿐이고, 산업 경로로 온 사건도 판정 단계 없이 바로 "배경 후보" 로 넘긴다(`ai/app/services/classification/assemble.py`).

기업–산업 연결에 들어가 있던 것 중 실제로는 기업–기업 관계인 것이 있다. 이 문서 방향이 정해지면 옮길지 검토한다.

| 지금 (INDUSTRY_MAP 3절) | 실제 관계 |
| --- | --- |
| SK스퀘어 → 메모리반도체 (`ownership`) | SK하이닉스 → SK스퀘어 `ownership` |
| LG화학 → 배터리셀 (6절 1번 후보) | LG에너지솔루션 → LG화학 `ownership` |
| 삼성물산 → 바이오의약품 (후보) | 삼성바이오로직스 → 삼성물산 `ownership` |
| 두산 → 발전설비 (후보) | 두산에너빌리티 → 두산 `ownership` |
